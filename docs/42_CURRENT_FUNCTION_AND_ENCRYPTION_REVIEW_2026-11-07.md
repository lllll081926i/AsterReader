# 当前功能缺口与加密设计复审（2026-11-07）

审查基线：407389e。范围：当前主源集、数据库、扫描与归档、备份、安全设置，以及安全文档 11、19、23、25、27、29、32 和安全架构图。本报告是静态审查，不表示所有设备交互或安全攻击场景已经验证。

## 1. 结论与状态边界

本地漫画导入、阅读、搜索、书架、进度和封面已经有真实实现，不能归为纯空架子。当前仍缺少可靠后台扫描、完整恢复链路和部分安全设置防护。

当前只有应用锁与隐藏作品访问锁。隐藏作品的原文件、数据库元数据和阅读缓存仍可能是明文。当前 UI 使用“访问锁”语义是正确的，不能把这些数据描述为已加密。

`00_START_HERE.md:3` 明确把 Vault 标记为“已搁置，未实现”。但 `27_FINAL_ARCHITECTURE_DECISIONS.md` 的 ADR-008、ADR-019、ADR-020 和 `29_DEFINITION_OF_DONE_AND_GATES.md` 的 Alpha 门禁仍要求真实 Vault。应通过状态说明或 ADR 统一范围；本次没有擅自重新启用这项规划。

优先级：P1 为当前应优先处理的可靠性或安全缺口；P2 为产品完整性、工程或验收缺口。D 类是加密实施前必须补齐的设计约束，不代表已经存在对应的加密代码漏洞。

## 2. 当前应用问题

### F01 · P1 · 关闭应用锁不要求重新验证

证据：`PrivacySecuritySettingsScreen.kt:88` 直接调用 `setAppLockEnabled`；`AsterViewModel.kt:716` 的实现直接更新并保存状态，没有新认证。

影响：他人在应用已解锁的窗口内可以关闭应用锁。这里不是“从锁屏直接绕过”，而是缺少敏感设置的再次认证。文档 19 第 15 节明确要求关闭锁之前认证。

处理：关闭应用锁、降低认证策略等动作使用绑定具体操作的一次性认证结果。取消、后台、进程重建或凭据变更后不得执行旧操作。

验收：直接关闭必须进入认证；取消、失败和过期不得改变设置；认证成功只执行对应操作一次。

### F02 · P1 · 扫描切后台会取消，不能续扫

证据：`AsterViewModel.kt:738` 的 `onBackground()` 主动取消扫描；`:1337` 使用 ViewModel 协程，没有持久化任务游标。

影响：切换文件管理器、锁屏或临时离开应用，可能留下仅导入一部分的目录。已有成功记录保留，但恢复时需要重新扫描。

处理：后台任务保存任务状态与逐项结果；恢复后重新核对来源并续扫。涉及未来加密任务时，还必须服从密钥会话的暂停与清理约束，不能只机械改成常驻后台。

验收：扫描大量漫画时后台、杀进程、恢复；记录不重复，成功项保留，任务明确显示暂停、取消或完成。

### F03 · P1 · 扫描结果没有可回查的逐项记录

证据：`LibraryRepository.kt:46` 的失败原因是分类字符串集合；`AsterViewModel.kt:1337` 完成后仅发 Snackbar。当前隐藏命中提示已经修复，不应重复认定为未修复。

影响：提示消失后，用户无法查看哪些公开文件失败、哪些被忽略、是否扫描完整，也不能定向重试。

处理：增加任务详情页、公开失败项目与重试。隐藏项目未认证前只给通用提示和数量；不能把私密标题或路径写入普通任务表。

### F04 · P1 · 临时授权副本缺少原来源身份映射

证据：`LibraryRepository.kt:246` 的 `importManagedDocument()` 每次创建随机目录，把应用持有文件的 URI 交给导入流程，没有持久化原 content URI 与副本的映射。

影响：不能持久授权的同一文档再次导入时，可能生成另一份副本与作品记录。新修复的 SAF authority/documentId 去重不能覆盖这个分支。

处理：保存来源身份与持有副本的关联；在必要时使用受限内容摘要复核。不能仅按文件名合并不同漫画。

验收：同一临时授权来源重复导入不重复占用空间、不丢进度；同名不同内容仍可分别导入。

### F05 · P1 · 归档资源限制覆盖不一致

证据：`ComicArchive.kt:183` 的 ZIP 和 `:201` 的 7Z 实现先完整枚举条目；EPUB 的 `:149` 使用 DOM 读取 XML，没有在该入口限制解压后的 XML 字节数。`LibraryRepository.kt:897` 的封面解码流没有阅读器 `DocumentRenderSession.kt` 的字节限制。

影响：小体积但条目极多、XML 极大或压缩比极高的归档可能造成内存或 CPU 压力。这是源码确认的防护缺口，本轮没有执行恶意样本，不能声称已复现崩溃。已有 TAR 检查和阅读页面解码限制不等于所有入口都有保护。

处理：统一条目数量、名称长度、单条目解压大小、累计解压预算、解析取消和封面流限制；在无信任元数据时用实际读取计数执行限制。

### F06 · P2 · 重新扫描不等于强制重新校验内容

证据：`LibraryRepository.kt:170` 在大小与修改时间相同且状态正常时直接返回已有记录。

影响：Provider 保留修改时间、原位替换同尺寸文件时，重扫可能不更新页数或封面。这是有条件的缓存一致性风险；不是所有增量扫描都有问题。

处理：区分日常增量扫描与强制校验；强制校验重新解析并刷新内容身份。不要把每次日常扫描都变成全库完整哈希。

### F07 · P2 · 单文件来源缺少统一重扫入口

证据：`AsterViewModel.kt:1371` 的重扫遍历仓库；没有仓库时只尝试补封面并提示选择目录。

影响：仅用“添加文件”建立的书库无法通过同一重扫入口统一刷新原文件变化。

处理：把可重新访问的单文件纳入来源维护；授权失效时定向重新定位，保留阅读记录。

### F08 · P2 · 格式兼容仍有明确边界

证据：`ComicArchive.kt:227` 明确拒绝 RAR5；`:30` 的归档图片筛选依赖内部文件扩展名；`LibraryRepository.kt` 单文件限制 512 MiB。

欠缺：RAR5、密码归档、嵌套归档集合、大于上限的漫画；归档内部无后缀或错后缀图片仍会被跳过。外层 ZIP 的文件头识别已经实现，不代表内部每张图片也做了文件头识别。AVIF/HEIF 等仍受设备解码能力影响。

处理：建立真实格式样本矩阵，优先补常见 RAR5；密码归档需要凭据生命周期设计。对不支持格式明确报告原因，不能无限承诺“全部格式”。

### F09 · P1 · 当前清单不能承担完整备份

证据：`LibraryBackup.kt:40` 导出公开元数据并排除隐藏作品；不包含漫画字节。系统备份与设备迁移在 `data_extraction_rules.xml` 中均被排除。

影响：目前隐私默认较保守，但没有完整内容恢复路径。清数据或卸载会丢失未主动导出的应用记录；应用持有的 `files/imports` 副本也会随应用数据丢失。外部原文件不会因此被应用删除。恢复密码本身也不能替代文件备份。

处理：分别定义公开清单、完整内容备份和未来加密备份；明确覆盖范围、空间需求、恢复校验和重新授权行为。继续保留当前默认不导出隐藏内容的行为。

### F10 · P2 · 恢复前没有所选文件的具体预览

证据：`SettingsScreen.kt:185` 的恢复入口先显示通用确认，再打开选择器；`AsterViewModel.kt:1299` 读取选定文件后直接执行恢复。

影响：用户无法提前看到所选清单版本、条目数量、冲突和合并结果。现有格式验证与事务恢复是真实实现，应保留。

处理：先解析为恢复计划，再展示新增、更新、跳过、冲突与来源失效数量；用户确认后原子提交。

### F11 · P2 · PIN 安全说明与升级格式不足

证据：`ReaderPreferences.kt:19` 声称 4–8 位 PIN 使用 6 万次 PBKDF2 后“不至于被暴力枚举”；`:25` 固定迭代次数，`:32` 的 v2 凭据没有携带迭代参数。旧静态盐摘要只在修改 PIN 时升级。

影响：4 位数字只有 10,000 种组合，不能作离线抗猜测承诺；当前 UI 冷却限制不能约束离线攻击。未来调整参数也必须保留旧凭据解释规则，不能直接改常量导致旧 PIN 全部失效。

处理：修正说明；新凭据使用版本化参数，旧格式成功验证后安全升级。恢复密码槽不能复用短 PIN 策略。提高成本前需在最低支持设备测量延迟。

补充风险：`AsterViewModel.kt:642` 的 PIN 冷却依赖墙上时钟，系统时间改变可能改变剩余时长；需定义跨重启与改时钟策略，不应等同于硬件防暴力破解。

### F12 · P2 · 认证能力与文档不同

证据：`AsterViewModel.kt:716` 开启应用锁前必须先设置 App PIN；`SystemBiometrics.kt:59` 的系统验证只返回成功回调，没有加密操作。

现状：当前是 App PIN 与可选系统验证的访问门禁，没有文档规划的完整系统认证独立配置、AND 策略、恢复槽和认证绑定 Vault 解封流程。没有 CryptoObject 本身不是当前访问锁的密码学漏洞；未来 Vault 不能直接沿用成功布尔值代替密钥授权。

### F13 · P2 · 搜索与大书库性能尚未闭环

证据：`LibrarySearch.kt:23` 接收全量作品与批注列表，在后台线程逐项筛选排序；`AsterDao.kt:14` 返回全量作品。

影响：小书库可用，但尚无分页、分层索引或万本真实库性能证据。当前已避免在主线程进行搜索计算，不能把它误报为主线程阻塞。

处理：先做 Release/R8 大库基准，再按瓶颈引入分页或索引。受保护信息不能进入普通明文索引。

### F14 · P2 · 页面架构仍偏集中

证据：`settings.gradle.kts` 仅包含 app、core:model、core:database、core:designsystem；导航仍由 `AsterViewModel.kt` 的自定义子页面栈维护，渲染和安全逻辑集中在 app。

欠缺：冻结规范中的 Navigation 3、Material3 Adaptive 导航、Hilt、Reader Engine 与安全模块边界尚未全面落地。已有断点侧栏和双栏是真实适配，不能称作完全没有平板适配。

处理：先建立来源与认证边界，再逐步迁移导航和 Reader；不要只为模块数量拆空目录。

### F15 · P2 · 首次引导、诊断和许可交付不完整

证据：`MainActivity.kt:527` 能渲染 Onboarding 路由，但未发现首次启动完成标记与自动进入链路；`SettingsScreen.kt:189` 的诊断页仅展示环境数据，关于页仅版本与包名。

欠缺：首次引导闭环、主动脱敏诊断导出、依赖许可正文和 NOTICE 展示入口。WebDAV/同步也未实现，但冻结范围允许远程能力后置，不应作为本地阅读的阻断项。

### F16 · P2 · UI 一致性与设备验收仍有尾项

证据：`PrivacySecuritySettingsScreen.kt:95` 向安全选项传入说明文字，`AsterComponents.kt:629` 仅在选项不可用时显示该说明；PIN 表单用单独“保存”按钮，设置中的若干 AlertDialog 仍使用独立 TextButton 排列。业务字符串和部分尺寸仍散落在页面。

影响：按钮处理不完全符合此前“按钮成对等宽并尽量带图标”的要求。禁用原因说明与普通选项说明需要分别验收；不能误报为全部选项仍有说明。单动作表单是否属于允许的特殊场景尚无明确记录。

处理：按组件和页面矩阵审查所有正常、空、错误、锁定状态，统一安全表单与对话框动作。API31/API37 设备、TalkBack、预测返回、折叠态、Reduced Motion 动效和真实系统认证尚未完成完整人工验收；已有 Robolectric 截图不能替代这些验收。

## 3. 加密文档评审

主文档：`19_SECURITY_VAULT_AND_APP_LOCK.md`。交叉审查：11、23、25、27、29、32 与 `diagrams/security_vault.mmd`。

合理的部分：区分访问锁与加密锁；每对象独立 DEK；Keystore 包装主秘密；认证加密；按需随机读取；禁止完整明文临时文件；元数据单独保护；迁移先验证后删除；无恢复槽时明确密钥丢失后果。这些方向可以保留。

总体判断：可作为架构草案，尚不能直接作为生产加密协议规范。以下问题必须在实现前明确。

### D01 · 删除原文件前的校验标准相互冲突

文档 19 第 10 节要求验证全部 chunk tag；文档 32 第 5 节却允许 sampled/full 按策略校验。

修订要求：凡允许删除原文件，必须重新读取已持久化密文，验证完整结构、全部块认证与逻辑长度；必要时与写入阶段摘要比对。抽样只可用于非破坏性的后台巡检。同步明确空文件、尾随数据和损坏最后一块的行为。

### D02 · 恢复密码 KDF 没有可实施的规格

文档 19 第 3、6 节只有“8+ 字符”和“KDF”，没有算法、盐、成本、参数编码、Unicode/编码规则和参数升级。无法据此判断离线抗猜测能力。

修订要求：选择经过审查的 KDF，给出参数与设备基准；独立随机盐，参数与版本随槽保存并认证；限制导入时参数上限以防资源消耗攻击。优先引导较长随机口令，不能把 8 字符视为安全保证。

参考：[OWASP 密码存储规范](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。其工作因子可作设计参考，不能脱离移动设备性能直接抄常量；短 PIN 的熵不足仍然存在。

### D03 · OR、AND 与恢复槽没有形成完整密钥策略

文档 19 第 3 节允许任一或双重认证，但第 6 节画的是多个入口分别包装同一主秘密。两个槽各自独立解封同一主秘密，实质是 OR；“两个界面都点过”不能自动形成密码学上的 AND。

修订要求：逐项定义系统认证、App PIN、强密码、恢复口令能解封哪些槽；哪些只是界面门禁；AND 如何组合与恢复；恢复是否绕过日常 AND。明确弱恢复槽会降低整体离线防护。当前 PIN 校验摘要不能用来恢复加密密钥。

### D04 · Keystore 认证参数与失败降级未写完整

文档 19 第 7 节只给出认证必需与允许的认证类型，没有精确列出 `setUserAuthenticationParameters(timeout, type)`、认证绑定方式和失效后的行为。

修订要求：明确逐次或限时授权模型，区分 BiometricPrompt 的认证器常量与 KeyProperties 的密钥授权常量。StrongBox 不可用可回退普通 Keystore，但不能静默去掉用户认证要求；检查并记录非敏感的硬件安全级别。无锁屏、密钥失效与设备迁移需有明确状态。

参考：[Android Keystore](https://developer.android.com/privacy-and-security/keystore)、[KeyGenParameterSpec.Builder](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder#setUserAuthenticationParameters(int,%20int))。

### D05 · 容器头与文件结束边界没有完整认证定义

文档 19 第 8 节中的 `headerTag / authenticated metadata` 仍是示意字段；未定义其密钥、nonce、覆盖范围和验证顺序。当前 AAD 列表没有明确绑定完整头、总长度、块大小和尾块语义。

修订要求：指定不可变头部的规范编码与认证范围；总长度、块数、块大小、对象 ID、算法与版本必须受到认证。定义 EOF 与认证错误的区别、完整块截断检测、空文件和多余尾部处理。已有随机访问读到的块通过认证，不代表未读部分已经完整校验。

参考：[Tink AES-GCM-HKDF Streaming 规范](https://developers.google.com/tink/streaming-aead/aes_gcm_hkdf_streaming)明确区分最终块并提醒 EOF 与解密错误不能混淆。可评估经审查的分块实现是否满足 AES-256、随机访问和容器要求；不能把它的参数机械拼入现有草案。

### D06 · nonce 方案的重试与上限缺失

64 位文件前缀加 32 位块号，在每文件全新 DEK 且块号不重复的前提下可以成立，不能仅因为前缀 64 位就判错。但草案没有规定块号溢出、重试、断点续传、修改文件和 header 加密的 nonce 域。

修订要求：每个 DEK 下每个 nonce 只能用于一次加密；重启写入优先使用新文件代次与全新 DEK，或证明已有块不会改写。给出最大块数与文件大小，禁止计数回绕。头、元数据与 DEK 包装采用独立密钥域或严格独立 nonce 管理。

### D07 · 密钥包装本身的协议缺失

文档说明谁包装谁，却没有规定包装算法、IV/tag 存储、AAD、槽标识、vaultId/fileId 绑定、主密钥代次和轮换事务。

修订要求：定义每个包装层的认证加密格式与用途分离；对象跨 Vault、跨代次或跨用途替换必须失败。导入包装对象需有长度与资源限制。修改恢复密码先写入并验证新槽，再提交替换，失败保留旧槽。

### D08 · 源文件删除缺少并发变化防护

文档 19 第 10 节按“读源→加密→验证→删除”描述，没有约束加密期间源文件被替换或修改。

修订要求：记录来源身份与版本；删除前核对当前来源仍为被迁移的版本。Provider 无法提供稳定版本时需重新核验或要求保留源文件。任务恢复后不得仅按旧 URI 直接删除新文件。

另外，删除闪存或云端文件不能承诺物理擦除，其他应用副本、云版本和旧备份仍可能存在。此限制应写进威胁模型和迁移确认。

### D09 · 文件系统与数据库没有共同事务

文档 19 的“Atomically commit vault record”容易被误解为同时提交文件和数据库。文档 32 已提醒 SAF 不保证原子重命名，但尚无完整恢复状态表。

修订要求：定义 staging 写入、持久化、完整验证、不可变对象发布、DB 提交、可选删除的日志状态。逐个说明每一步断电后的恢复动作、孤立密文与缺失索引处理。恢复逻辑不得优先删除唯一可恢复副本。

### D10 · 重新上锁后的内存与后台任务约束不足

文档 19 第 9 节说 session 关闭后清理，但没有会话代次、进行中的随机读取、预取、渲染回调与后台迁移如何撤销。

修订要求：锁定先遮盖并撤销会话，再取消任务和清缓存；旧回调不得把已解密位图重新发布。明确会话密钥是否继续保留、后台加密何时暂停。托管内存和图形内存不能保证所有物理副本即时归零，不能作绝对承诺。

### D11 · 元数据和备份语义仍有歧义

文档 19 把 original path/name 标为“可配置”，但路径和文件名本身经常包含书名。密钥“永不进入 backup”的表述又与主动备份中的 wrapped Master Secret 冲突。

修订要求：真实源路径、书名、封面、批注、搜索历史与包含私密标签的导航状态均纳入敏感数据清单；公开壳仅保留最小随机标识与必要状态。明确禁止备份的是明文秘密与设备绑定材料；用户主动加密备份可包含经过认证包装的恢复材料。

备份 manifest、文件清单与数据库快照也要认证并按敏感程度加密，防止只加密正文却泄漏标题或接受被替换的对象。恢复密码只有在密文、包装密钥与元数据备份仍存在时才有恢复价值。

### D12 · 防回滚、恶意输入与发布测试不完整

AES-GCM 验证通过不能证明文件是最新版本，也不能证明用户已撤销的旧恢复槽没有被回滚。威胁模型需要明确是否防御整库回滚；不能默认获得离线反回滚能力。

验收至少增加：完整尾块截断；伪造长度和整数溢出；头与对象互换；重试导致的 nonce 复用；源文件变化；恢复槽增删中断；导入 KDF 参数攻击；锁定期间并发渲染；无恢复槽且密钥永久失效；旧备份不能被新密码“撤回”的提示。容器解析器还需模糊测试。
