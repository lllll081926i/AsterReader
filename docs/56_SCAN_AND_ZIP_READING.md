# 扫描入库、ZIP 阅读与设置尺寸（2026-11-08）

改动模块：`app`、`:core:database`、`:core:designsystem`。

## 问题与处理

- 原扫描复用完整导入流程，会打开压缩包、建立页数目录和解码封面。即使 PDF 跳过封面，仍会初始化 PdfRenderer；扫描后还会启动批量补封面。
- 现在扫描只使用提供者的文件名、MIME、大小、修改时间和远程版本信息，逐作品事务入库。不读取文件内容、不复制整本、不生成页面或封面。
- 详情预读与首次阅读使用延迟索引。ZIP 直接读取中央目录，保持同一 ZipFile 与页面条目列表；读取单页不遍历或解压前页。优化 ZIP 条目建表，减少名称列表与按名称再次查找的开销。
- 图片尺寸与像素读取优先复用同一条 64 KiB 缓冲流；长文件头无法回退时才重开。尺寸索引和位图缓存继续复用，不降低清晰度、不启用低清预览。
- 缺失的公开封面复用阅读时已解码的封面页生成，不额外请求其他页；隐藏或加密作品不进入该封面保存路径。
- 设置页整体按原尺寸 1.5 倍布局，不使用图层拉伸。保留系统字体缩放和滚动，嵌套表单不重复放大。

## 数据契约

`totalPages=0` 表示尚未建立阅读索引，不能视为零页文档，也不能据此写入阅读位置。源文件变化后清除旧页数、目录与封面引用，保留用户状态；延迟索引事务提交时核对来源版本，拒绝过时结果。无需数据库迁移，Vault 格式和用户原件不变。

目录扫描按扩展名或 MIME 识别候选。无后缀或错误后缀需要通过单文件导入识别文件头。损坏、非漫画或不支持的压缩内容在打开时反馈，扫描成功仅表示登记来源成功。
