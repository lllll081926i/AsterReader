# 阅读期间的后台开销优化

## 问题与实施

连续滚动约每 900 毫秒保存页内位置。原实现每次都更新 books 的阅读时间，因此同一页内的偏移变化也会使 Room 的整张书库表观察查询失效，重新创建书库列表。后台封面检查随后仍会排序全部作品并创建签名列表，最后才等待退出阅读页。书库越大，这部分重复处理越多。

本轮修改 core:database 与 app 的后台调度，不修改阅读画面、动画、预加载配置或解码清晰度。

- 页内偏移、缩放和平移继续按原保存节奏写入 reader_states；完全相同的状态不重复写入。
- 页码、进度百分比、阅读状态和章节变化仍在同一事务内更新 books 与 reader_states。事务失败仍整体回滚。
- 只有最近阅读时间变化时，books 最多每 30 秒更新一次；首次阅读和系统时间回拨仍立即更新。该间隔只影响书库的最近阅读时间，不影响页内位置恢复。
- 封面检查在创建全书库签名之前检查当前界面。扫描、应用锁定、阅读页和详情页期间跳过签名排序；恢复后台处理时使用最新书库与封面修订号。
- 每本封面生成前仍重新检查后台执行条件。已经开始的封面原生解码不承诺立即中断。

无数据库 schema 或数据迁移，无加密格式、依赖和版本号变化。保险库的进度保存流程保持原有授权和密文存储方式。本轮不发布。
